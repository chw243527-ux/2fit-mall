# 2FIT MALL — 소형 모바일 PWA 설치 배너·구매 바 UI 테스트 시나리오

> **목적:** 기성품·단체주문 상세페이지에서 PWA 설치 배너가 표시되더라도 하단 고정 구매 바와 겹치거나, 구매 버튼의 터치·가시성을 방해하지 않는지 실제 모바일 기기에서 검증합니다.

## 1. 테스트 대상과 준비

2FIT MALL은 Flutter Web 기반이므로 상세페이지와 구매 바의 반응형 레이아웃은 Flutter에서 처리되며, PWA 설치 배너와 iOS·Android 안전 영역은 웹 진입 화면의 CSS에서 보호합니다. PWA 설치 배너는 `beforeinstallprompt` 이벤트가 제공되는 브라우저에서만 나타날 수 있으며, 모든 브라우저에서 항상 재현되는 이벤트는 아닙니다.[1]

| 우선순위 | 실제 기기 또는 브라우저 | CSS 뷰포트 기준 | 확인 목적 |
|---:|---|---:|---|
| 필수 | iPhone SE 1세대 또는 동급 | 320 × 568 | 가장 좁은 폭에서 글자·버튼·하단 안전 영역 확인 |
| 필수 | Galaxy S 계열의 Samsung Internet 또는 Chrome | 360 × 740 전후 | PWA 설치 배너와 구매 바 동시 노출 확인 |
| 권장 | iPhone SE 2·3세대 | 375 × 667 | 짧은 높이와 홈 인디케이터 영역 확인 |
| 권장 | iPhone 14·15 | 390 × 844 | 기준 모바일 폭에서 디자인 밀도 확인 |
| 권장 | Galaxy S Ultra 또는 동급 | 412 × 915 전후 | 큰 Android 화면에서 과도한 여백 여부 확인 |

테스트에는 `재고가 있는 기성품 싱글렛` 한 개와 `단체주문 전용 상품` 한 개를 준비합니다. 기성품에서는 **바로구매** 또는 **200명 중 한 명이 되기** 버튼, 단체주문에서는 **단체주문** 버튼이 반드시 표시되어야 합니다. 테스트 시작 전에 해당 브라우저에서 `2fit-mall.co.kr`의 사이트 데이터를 삭제하거나 시크릿 탭을 사용해 PWA 설치 안내가 표시될 수 있는 상태를 만듭니다.

## 2. 공통 합격 기준

| 항목 | 합격 기준 | 실패로 판단하는 사례 |
|---|---|---|
| 배너·구매 바 간격 | PWA 배너의 하단과 구매 바의 상단 사이에 **최소 8px** 이상의 빈 공간이 유지됩니다. | 배너 그림자·버튼·배경이 구매 바 영역을 덮거나 맞닿습니다. |
| 구매 버튼 가시성 | 구매 바와 버튼 레이블이 100% 보이며, 하단 시스템 제스처 영역에 가려지지 않습니다. | 버튼의 하단이 잘리거나 홈 인디케이터와 겹칩니다. |
| 터치 가능성 | 배너가 보이는 상태에서도 구매 버튼, 찜 버튼, 배너 닫기와 설치 버튼을 각각 독립적으로 누를 수 있습니다. | 배너의 투명 영역이 구매 버튼 터치를 가로채거나, 버튼을 눌러도 반응하지 않습니다. |
| 가로 스크롤 | 화면 최하단과 상세페이지 전체에서 가로 스크롤이 생기지 않습니다. | 오른쪽 여백이 잘리거나 화면을 좌우로 밀 수 있습니다. |
| 텍스트 | 상품명·버튼 텍스트가 2줄 이상으로 비정상적으로 겹치지 않고, 글자 잘림 없이 읽힙니다. | `...` 처리 없이 겹침·오버플로·잘림이 발생합니다. |

## 3. 핵심 테스트 시나리오

### 시나리오 A — Galaxy S 계열에서 배너와 기성품 구매 바 동시 노출

| 단계 | 수행 방법 | 기대 결과 |
|---:|---|---|
| 1 | Samsung Internet 또는 Chrome을 열고 `https://2fit-mall.co.kr`에 접속합니다. | 사이트가 정상 로드되고 로그인합니다. |
| 2 | 재고가 있는 기성품 싱글렛 상세페이지를 엽니다. | 화면 하단에 고정 구매 바가 표시됩니다. |
| 3 | PWA 설치 배너가 나타날 때까지 초기 화면을 유지합니다. | 배너가 구매 바보다 위에 표시되며 두 영역이 겹치지 않습니다. |
| 4 | 배너가 열린 상태에서 상세페이지를 맨 아래까지 스크롤합니다. | 구매 바는 계속 보이고, 배너가 콘텐츠·구매 바를 가리지 않습니다. |
| 5 | 구매 바의 찜 버튼과 구매 버튼을 각각 한 번씩 누릅니다. | 두 버튼이 정상 반응하며 배너가 터치를 가로채지 않습니다. |
| 6 | 배너의 닫기 버튼을 누릅니다. | 배너만 사라지고 구매 바는 위치 변화 없이 유지됩니다. |

### 시나리오 B — iPhone SE 계열에서 구매 바와 안전 영역 확인

| 단계 | 수행 방법 | 기대 결과 |
|---:|---|---|
| 1 | Safari에서 2FIT MALL에 접속하고 기성품 상세페이지를 엽니다. | 페이지 폭이 화면을 넘지 않고 하단 구매 바가 표시됩니다. |
| 2 | 상세페이지를 맨 아래까지 스크롤합니다. | 마지막 안내 문구와 하단 구매 바가 동시에 읽히며, 버튼이 홈 인디케이터 위로 충분히 올라옵니다. |
| 3 | 화면을 세로·가로로 한 번 회전한 뒤 다시 세로로 돌립니다. | 구매 바가 다시 화면 너비에 맞고, 버튼과 찜 영역이 잘리지 않습니다. |
| 4 | 홈 화면에 추가한 뒤 독립 실행 상태에서 다시 상품을 엽니다. | 독립 실행 상태에서도 구매 바의 하단 여백이 유지됩니다. |

> iOS Safari에서는 자체 PWA 설치 방식으로 인해 페이지 내 설치 배너가 보이지 않을 수 있습니다. 이 경우에는 **배너 미노출 자체를 실패로 보지 말고**, 독립 실행 상태의 하단 구매 바와 안전 영역만 확인합니다.[1]

### 시나리오 C — 단체주문 상세페이지 버튼 보호

| 단계 | 수행 방법 | 기대 결과 |
|---:|---|---|
| 1 | Galaxy S 또는 iPhone SE에서 단체주문 전용 상품을 엽니다. | 하단에 **단체주문** 버튼이 표시됩니다. |
| 2 | PWA 설치 배너가 나타난 상태에서 버튼을 누릅니다. | 배너와 관계없이 단체주문 안내 또는 주문서 진입 흐름이 열립니다. |
| 3 | 안내 화면을 닫고 스크롤 위치를 변경합니다. | 구매 바가 여전히 화면 하단에 고정되며, 단체주문 버튼을 다시 누를 수 있습니다. |

### 시나리오 D — 짧은 화면과 배너 자동 종료

| 단계 | 수행 방법 | 기대 결과 |
|---:|---|---|
| 1 | iPhone SE 1세대 수준의 320×568 화면 또는 브라우저 기기 에뮬레이션을 사용합니다. | 본문 좌우 여백이 12px로 축소되어 콘텐츠 폭이 확보됩니다. |
| 2 | PWA 설치 배너가 나타난 뒤 8초 동안 대기합니다. | 배너가 자동으로 사라지고 구매 바가 정상적으로 남습니다. |
| 3 | 배너 노출 중 스크롤·찜·구매·닫기 동작을 모두 수행합니다. | 어떤 동작에서도 버튼이 가려지거나 화면이 가로로 밀리지 않습니다. |

## 4. 실패 시 기록 형식과 재현 정보

발견한 문제는 아래 항목과 함께 캡처합니다. 상태바와 하단 구매 바가 함께 보이도록 스크린샷을 남겨야 겹침 위치를 판단할 수 있습니다.

| 기록 항목 | 예시 |
|---|---|
| 기기·브라우저 | Galaxy S23 / Samsung Internet 27 |
| 화면 방향 | 세로 또는 가로 |
| 페이지·상품 | 기성품 싱글렛 / 상품명 |
| PWA 상태 | 배너 노출, 닫기 직전, 설치 후 독립 실행 |
| 재현 단계 | ‘상품 하단 스크롤 후 배너 표시’ |
| 화면 캡처 | 상태바·PWA 배너·구매 바가 한 화면에 보이도록 첨부 |

## 5. 자동·반복 점검

소스의 반응형 보호값은 아래 명령으로 반복 검증할 수 있습니다. 이 명령은 데이터를 변경하지 않습니다.

```bash
node tools/mobile-responsive-audit.js
```

이 스크립트는 320, 360, 375, 390, 412px 폭에서 폰트 스케일, 본문 여백, 최소 터치 영역, 하단 구매 바의 여백과 HTML·Flutter 보호 규칙의 존재 여부를 확인합니다.
