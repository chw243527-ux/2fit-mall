# 2FIT Mall 실제 기기 테스트 주요 시나리오

## 1. 테스트 목적과 우선순위

실제 기기 검수의 최우선 목적은 **결제 금액과 주문 데이터의 정확성**, **재고 정합성**, **사용자가 결제 후 정상적으로 복귀하는지 여부**, 그리고 **모바일·태블릿 화면에서 핵심 버튼을 사용할 수 있는지 여부**를 확인하는 것이다. 화면 색상이나 간격보다 결제와 주문 상태가 우선이며, 아래 시나리오 중 결제·재고·주문 데이터가 실패하면 공개 운영을 중단하고 원인을 먼저 수정해야 한다.

| 우선순위 | 영역 | 공개 운영 판정 |
|---|---|---|
| P0 | 결제 승인, 주문 생성, 금액, 재고 차감 | 하나라도 실패하면 운영 중단 |
| P0 | 로그인, 배송지, 결제 복귀 | 하나라도 실패하면 운영 중단 |
| P1 | 장바구니 실시간 재고, 옵션, 주문 내역 | 실패 시 해당 기능 공개 중단 |
| P1 | 단체주문 옵션·PDF·첨부파일 | 단체주문 기능 공개 전 필수 |
| P1 | Android 푸시 및 Play 설치 | Android 공개 전 필수 |
| P2 | 반응형 배치와 문구 표시 | 핵심 조작 불가 시 P1로 상향 |

## 2. 테스트 준비

테스트는 실사용자 계정과 관리자 계정을 분리해서 진행한다. 테스트 상품은 실제 판매 상품과 구분되는 상품을 사용하고, 테스트 결제가 가능한 환경인지 먼저 확인한다. 실결제를 사용할 경우 금액과 환불 담당자를 사전에 정하고, 가능하면 결제 제공자의 테스트 모드 또는 내부 테스트 상품을 사용한다.

테스트 기록에는 기기명, 운영체제 버전, 브라우저 또는 앱 버전, 네트워크 유형, 테스트 시각, 주문번호, 결제 승인번호, 상품 재고 전후 수량을 남긴다. 개인정보와 결제 비밀정보는 캡처 화면이나 문서에 포함하지 않는다.

권장 기기 조합은 최신 iPhone 계열 1대, Android 휴대폰 1대, iPad 또는 Android 태블릿 1대, 데스크톱 Chrome 1대이다. 모바일 데이터와 Wi-Fi를 각각 한 번 이상 사용하고, 가능하면 화면 확대 또는 글자 크기 증가 상태도 확인한다.

## 3. P0: 로그인과 권한

### 3.1 일반 사용자 로그인

1. 로그아웃 상태에서 사이트를 연다.
2. 일반 계정으로 로그인한다.
3. 홈, 상품 상세, 장바구니, 마이페이지를 차례로 연다.
4. 앱 또는 브라우저를 새로고침한 뒤 로그인 상태가 유지되는지 확인한다.
5. 로그아웃한 뒤 뒤로 가기나 저장된 URL로 관리자 화면에 접근한다.

**합격 기준:** 일반 사용자는 관리자 메뉴와 관리자 데이터에 접근할 수 없어야 한다. 로그인 후 새로고침해도 사용자의 장바구니와 주문 이력이 정상적으로 유지되어야 한다. 로그아웃 후 보호된 화면이 노출되거나 이전 사용자 정보가 남으면 실패다.

### 3.2 관리자 권한 분리

관리자 계정으로 로그인해 관리자 대시보드, 상품 관리, 재고 관리, 주문 관리, 고객 관리 메뉴가 표시되는지 확인한다. 일반 계정의 브라우저 세션에서 관리자 URL을 직접 입력해 접근을 시도한다.

**합격 기준:** 관리자에게만 관리 메뉴가 표시되고, 일반 사용자는 URL을 직접 입력해도 접근할 수 없어야 한다. 관리자 작업 후 일반 계정으로 전환했을 때 관리자 상태가 남아 있으면 실패다.

## 4. P0: 배송지와 결제

### 4.1 모바일 배송지 선택

모바일 브라우저에서 상품을 장바구니에 담고 주문서로 이동한다. 배송지 입력 화면에서 주소 검색을 실행하고, 검색 결과를 선택한 뒤 상세 주소를 입력한다. 키보드를 닫았다가 다시 열고 다음 단계로 진행한다.

**합격 기준:** 주소 검색 팝업 또는 외부 주소 서비스로 이동한 뒤 주문서로 정상 복귀해야 한다. 우편번호, 기본 주소, 상세 주소가 올바른 입력란에 들어가야 하며, 다음 버튼이 키보드나 하단 고정 영역에 가려지지 않아야 한다.

### 4.2 태블릿 결제 앱 복귀

태블릿에서 결제수단을 선택하고 Toss 결제 앱 또는 외부 결제 화면으로 이동한다. 결제 승인 후 쇼핑몰 앱 또는 브라우저로 돌아온다. 복귀 직후 화면을 닫거나 새로고침하지 말고 주문 완료 상태를 확인한다.

**합격 기준:** 결제 완료 후 주문 완료 화면으로 이동하고 주문번호가 표시되어야 한다. 결제 상태가 승인으로 저장되고 주문이 중복 생성되지 않아야 한다. 결제 앱에서 돌아온 뒤 무한 로딩, 흰 화면, 결제 완료 버튼 재노출이 있으면 실패다.

### 4.3 금액과 주문 데이터 검증

상품 가격, 옵션 추가금, 할인, 배송비, 최종 결제 금액을 주문 전 화면과 결제 승인 결과에서 비교한다. 결제 후 관리자 주문 상세와 사용자 마이페이지 주문 상세를 각각 확인한다.

**합격 기준:** 화면에 표시된 최종 금액, 서버가 검증한 금액, 결제 승인 금액, 주문 저장 금액이 모두 같아야 한다. 클라이언트 화면의 금액만 바꾸어 결제 승인이 되면 치명적 실패다.

### 4.4 실패·취소·중복 클릭

결제창에서 취소하고 주문서로 돌아온다. 결제 승인 직전에 네트워크를 끊었다가 복구한다. 결제 버튼을 빠르게 두 번 누르고, 결제 완료 후 새로고침한다.

**합격 기준:** 취소는 실패 또는 취소 상태로 명확히 표시되고 미완료 주문이 승인 주문으로 바뀌지 않아야 한다. 같은 결제에 주문이 두 건 생성되거나 재고가 두 번 차감되면 실패다.

## 5. P0: 재고 정합성

### 5.1 정상 구매 차감

재고가 1개인 상품을 한 개 주문하고 관리자 화면에서 재고가 0으로 바뀌는지 확인한다. 같은 상품을 다른 기기에서 다시 장바구니에 담거나 결제한다.

**합격 기준:** 정상 주문은 정확히 한 번만 차감된다. 재고가 0이 된 뒤 다른 사용자는 구매할 수 없어야 한다.

### 5.2 장바구니 보관 중 품절

기기 A에서 상품을 장바구니에 담는다. 기기 B 또는 관리자 화면에서 재고를 0으로 변경한다. 기기 A의 장바구니를 새로고침하거나 일정 시간 기다린다.

**합격 기준:** 가격·상품 정보·재고 상태가 실시간 또는 재진입 시 갱신되어야 한다. 품절 상품은 결제 단계에서 차단되고, 사용자에게 품절 상태가 명확히 표시되어야 한다.

### 5.3 관리자 재고 수정

관리자 화면에서 전체 재고, 색상별 재고, 사이즈별 재고를 각각 수정한다. 재고를 0으로 낮춘 뒤 양수로 복원한다. 상품 목록, 상품 상세, 장바구니에서 변경 결과를 확인한다.

**합격 기준:** `stockData`, `sizeStocks`, `stockCount`가 서로 일치해야 한다. 저장 직후 다른 화면에서도 같은 수량이 보여야 한다. 0에서 양수로 복원했을 때 재입고 알림 상태가 중복되지 않아야 한다.

## 6. P1: 상품·옵션·장바구니

색상 옵션이 있는 기성품을 선택해 색상별 상품 카드와 상세페이지를 확인한다. 색상 추가금이 없는 옵션은 추가금이 붙지 않는지 확인한다. 같은 디자인의 다른 색상을 각각 장바구니에 담는다.

**합격 기준:** 색상 선택 상태가 체크표시나 불필요한 장식 없이 일관되게 표시되어야 한다. 주문 내역에는 선택한 각 색상과 수량이 모두 표시되어야 한다. 색상별 재고가 실제 구매 가능 수량과 일치해야 한다.

장바구니에 상품을 담은 뒤 표시되는 장바구니 바로가기 버튼을 누른다. 좁은 화면에서 버튼과 가격, 수량 조절기가 겹치지 않는지 확인한다.

**합격 기준:** 장바구니 담기 후 바로가기 동작이 활성화되고, 텍스트가 잘리지 않으며, 수량 변경 결과가 총액에 즉시 반영되어야 한다.

## 7. P1: 단체주문과 PDF

싱글렛, 싱글렛 세트, 라운드티, 기타 단체주문 카테고리를 각각 테스트한다. 각 카테고리의 인쇄 옵션이 요구된 목록과 일치하는지 확인한다. 개인 이름 적용 옵션을 선택했을 때만 인원별 이름 입력칸이 활성화되는지 확인한다.

하의가 있는 주문에서는 남녀 하의 선택, 남성 3부 제한, 주머니 선택, 허리밴드 색상, 상세 사이즈 입력을 확인한다. 하의 사이즈 선택이 비활성화된 상품에서는 허리밴드 선택과 참고 이미지 업로드 영역이 숨겨져야 한다.

주문서에 상품 이미지, 선택 색상과 색상 코드, 디자인 파일, 로고 파일, 허리밴드 참고 이미지, 모든 인쇄 옵션을 입력하고 주문을 저장한다. 고객용 PDF와 발주용 PDF를 각각 다운로드한다.

**합격 기준:** 주문서에서 선택한 값이 PDF에 빠짐없이 유지되어야 한다. 고객용 PDF에는 고객 정보와 가격이 포함되고, 발주용 PDF에는 가격과 고객 민감정보가 제외되어야 한다. 첨부파일 링크가 열리고 이미지 미리보기가 가능한 경우 이미지도 정상 표시되어야 한다.

## 8. P1: Android 앱과 푸시 알림

Play Internal Testing 버전을 설치하고 로그인한다. 앱을 백그라운드로 보냈다가 다시 열고, 화면을 잠근 상태에서도 알림을 확인한다. 관리자 계정에서 테스트 알림을 발송하고 Android 알림 권한을 허용한 상태와 거부한 상태를 각각 확인한다.

**합격 기준:** 권한을 허용하면 알림이 수신되고, 알림을 누르면 올바른 화면으로 이동해야 한다. 권한을 거부한 경우 앱이 멈추지 않고 설정 안내를 표시해야 한다. 토큰 등록 실패가 사용자에게 원시 서버 오류로 노출되면 실패다.

## 9. P2: 반응형·접근성·성능

모바일 세로, 모바일 가로, 태블릿 세로, 태블릿 가로, 데스크톱 화면에서 홈, 카테고리, 상품 상세, 장바구니, 주문서, 완료 페이지, 마이페이지, 관리자 화면을 확인한다.

다음 현상을 중점적으로 찾는다.

- 상품명, 가격, 옵션명이 잘리거나 겹치는 현상
- 버튼이 화면 밖으로 밀리는 현상
- 팝업이 화면 높이를 초과하는 현상
- 키보드가 입력란이나 다음 버튼을 가리는 현상
- 이미지가 비율을 깨뜨리거나 로딩 중 레이아웃을 흔드는 현상
- 가로 스크롤이 의도하지 않게 생기는 현상
- 색상 대비가 낮아 선택 상태를 구분하기 어려운 현상

**합격 기준:** 핵심 작업을 가로 스크롤 없이 수행할 수 있어야 한다. 상품 이미지와 텍스트가 겹치지 않아야 하며, 키보드가 열린 상태에서도 현재 입력란과 진행 버튼을 사용할 수 있어야 한다.

## 10. 장애 대응과 최종 판정

테스트 중 오류가 발생하면 즉시 반복 클릭하지 말고 다음 정보를 기록한다. 기기와 OS, 브라우저 또는 앱 버전, 네트워크, 로그인 계정 유형, 테스트 시각, 주문번호, 화면 캡처, 오류 문구, 재현 순서를 함께 남긴다.

다음 항목은 즉시 운영 중단 사유다.

- 결제 승인 금액과 주문 금액 불일치
- 결제는 성공했지만 주문이 생성되지 않음
- 주문은 생성됐지만 재고가 차감되지 않음
- 한 번 결제했는데 주문이 중복 생성됨
- 다른 사용자의 주문 또는 관리자 정보가 노출됨
- 결제 앱 복귀 후 상태가 확정되지 않음
- 품절 상품을 구매할 수 있음
- 단체주문서의 선택사항이나 첨부파일이 PDF에서 누락됨

최종적으로 P0 시나리오가 모두 통과하고, P1 시나리오에서 치명적 결함이 없으며, P2 시나리오에서 핵심 조작을 방해하는 문제가 없어야 단계적 실사용 공개를 진행한다. 첫 공개 후 30분 동안 Cloud Functions 로그, 결제 승인 상태, 재고 변경, 운영 모니터링 결과를 함께 확인한다.
