## 1. 최종 결론

현재 웹과 코드 품질 측면의 자동 검증 기반은 상당 부분 정리되어 있습니다. 최신 `main` 커밋에서는 Web Deploy, Flutter CI, Dart Analyze Gate, Security Audit, Release Security Verification이 성공했습니다. Flutter 테스트도 로컬에서 전체 통과했고, Dart 포맷 검사와 `dart fix --dry-run`, 정적 분석도 통과했습니다.

다만 **Android 앱은 아직 최종 배포 상태가 아닙니다.** Google Play Internal Testing 업로드가 `minSdkVersion 23` 때문에 거부되었고, Google Play 요구사항에 맞추려면 최소 SDK를 24 이상으로 조정해야 합니다. Android는 사용자가 말한 것처럼 최종 수정이 모두 끝난 뒤 별도로 배포해야 하며, 그 전까지 Android 업로드 workflow를 성공 기준으로 간주하면 안 됩니다.

또한 custom lint가 GitHub runner에 `rg`가 없을 때 실제 검사를 수행하지 못하고 성공하는 문제가 확인되었습니다. 이 문제는 코드 품질 게이트의 신뢰성을 떨어뜨리므로 **최우선 자동화 보완 항목**입니다.

현재 출시 판단은 다음과 같습니다.

> **웹:** 자동 검증상 배포 가능한 수준에 가까우나, 운영 데이터와 실제 결제·알림·권한의 수동 검수가 필요합니다.
> **Android:** `minSdkVersion` 수정, custom lint 실행 보장, Android release 재빌드, Play Internal Testing 재검증 전에는 배포하지 않습니다.

## 3. 제가 바로 처리할 수 있는 항목

다음 작업은 저장소 코드, CI 설정, 테스트, 로그 분석만으로 처리할 수 있습니다. 사용자의 계정 조작이나 실제 결제 없이 진행할 수 있으므로 우선 자동으로 수정·검증할 대상입니다.

### 3.1 최우선: CI 신뢰성 보완

1. `ci_custom_lint.sh`에서 `rg`가 없으면 조용히 통과하지 않고 즉시 실패하도록 변경합니다.
2. GitHub Actions workflow에 `ripgrep` 설치 단계를 추가하거나, 외부 도구 의존성을 없애고 `grep`·`find` 기반으로 검사하도록 변경합니다.
3. custom lint가 실제로 실행되었음을 확인할 수 있도록 검사 파일 수와 검사 범위를 로그에 출력합니다.
4. CI에서 custom lint가 의도적으로 실패하는 테스트용 임시 파일을 만들었다가 삭제하는 자체 검증을 추가할 수 있습니다.
5. 모든 Flutter workflow가 같은 품질 게이트를 실행하는지 자동 점검합니다.

### 3.2 Android 최종 배포 차단 항목

1. `android/app/build.gradle.kts`의 `minSdk = 23`을 프로젝트 호환성 검토 후 24 이상으로 변경합니다.
2. NDK 의존성 경고가 반복되지 않도록 plugin이 요구하는 NDK 버전을 확인하고 필요한 경우 `ndkVersion`을 명시합니다.
3. Android release 빌드에서 포맷, `dart fix`, custom lint, 분석, 테스트, AAB 생성까지 순서대로 검증합니다.
4. Android Play 업로드 workflow를 재실행하고 Google Play의 거부 사유가 사라졌는지 확인합니다.
5. Android 배포 전용 체크리스트를 현재 코드 기준으로 갱신합니다.

단, `minSdk` 변경은 일부 구형 Android 기기 지원 범위를 낮출 수 있으므로 실제 지원 대상 Android 버전을 결정해야 합니다. 지원 범위를 24 이상으로 확정하면 코드 수정은 제가 진행할 수 있습니다.

### 3.3 웹 코드 및 기능 보완

1. 결제 취소 후 웹 복귀, 재결제, 주문 중복 생성 방지 흐름을 코드와 테스트로 다시 점검합니다.
2. 주문 payload의 사이즈·색상·수량·custom option 필드가 장바구니, 결제 승인, 주문 상세, 관리자 상세에서 동일하게 유지되는지 비교합니다.
3. 재고 변경 시 `stockData`, 사이즈별 재고, 집계 재고, 품절 표시가 같은 기준을 사용하는지 전수 확인합니다.
4. 재고 0→양수 변경 시 재입고 알림의 중복 방지와 레거시 필드 호환을 코드 수준에서 점검합니다.
5. 일반 상품의 여러 색상과 여러 사이즈 조합이 장바구니에서 각각 별도 옵션으로 보존되는지 회귀 테스트를 보강합니다.
6. 단체주문 상품에서 상품 변경 시 디자인 참고 이미지, 로고, 허리밴드 이미지, PDF 파일 상태가 초기화되는지 테스트합니다.
7. 첨부파일이 없는 경우 표시 영역이 남지 않고, 있는 경우 주문 상세와 PDF에서 정상 링크가 생성되는지 확인합니다.
8. PC·태블릿·모바일에서 장바구니 완료 팝업, 추천상품 카드, 장바구니 보기, 쇼핑 계속하기 버튼의 줄바꿈과 오버플로를 점검합니다.
9. 홈 화면 초기 로딩에서 배너만 보이고 상품 목록이 늦게 나타나는 경로에 로딩·실패·빈 상태 처리를 보완합니다.
10. Kakao 웹/iOS callback이 동의 후 로그인 화면에 남는 경로를 timeout, callback 복귀, 세션 복원, 중복 callback 관점에서 재검토합니다.

### 3.4 보안·운영 자동화

1. 보안 감사 스크립트가 읽기 전용으로 계속 실행되는지 확인합니다.
2. Firestore Rules와 Storage Rules에 대한 emulator 기반 테스트를 추가할 수 있는지 확인합니다.
3. 관리자 claim이 없는 사용자의 관리자 함수 직접 호출 실패 테스트를 추가합니다.
4. 주문 승인·재고 예약·결제 취소 함수의 멱등성 회귀 테스트를 추가합니다.
5. CI 로그에서 토큰, 결제 시크릿, 서비스 계정, 원시 예외가 노출되지 않는지 자동 검사합니다.
6. workflow 파일마다 `continue-on-error`가 보안·분석·테스트 단계에 남아 있지 않은지 검사합니다.
7. 웹 배포 후 HTTP 응답, 주요 JavaScript 오류, 기본 페이지 응답을 자동 확인하는 smoke test를 보완합니다.

## 5. 현재 확인된 오류와 보완 우선순위

### P0: 배포를 보류해야 하는 항목

#### Android 최소 SDK 오류

최신 Android Play 업로드에서 다음 오류가 확인되었습니다.

```text
Play automatic protection requires a minimum SDK version of 24 or higher.
The uploaded App Bundle has a minimum SDK version of 23.
```

현재 저장소의 Android 설정에는 `minSdk = 23`이 남아 있습니다. Android 최종 배포 전 24 이상으로 조정하고 AAB를 다시 만들어야 합니다.

#### custom lint가 실제로 실행되지 않을 수 있는 문제

GitHub runner에서 `rg: command not found`가 발생했지만 현재 스크립트는 `|| true` 때문에 검사를 성공으로 처리했습니다. 이는 품질 검사가 실행되지 않았는데 통과하는 문제입니다. `rg`를 설치하거나 POSIX 도구로 교체하고, 도구 미설치 시 반드시 실패하도록 수정해야 합니다.

#### 실결제·재고·권한의 운영 검수 미완료

자동 테스트는 코드 구조와 테스트 데이터를 검증하지만, 실제 Toss 결제 승인, 결제 취소, 재고 동시성, FCM 수신, Firebase Rules의 운영 프로젝트 권한을 완전히 대체하지 못합니다. 이 항목들은 사용자의 실제 운영 계정과 기기에서 확인해야 합니다.

### P1: 웹 운영 전 확인할 항목

- Kakao 로그인 callback이 iPhone Safari에서 정상적으로 완료되는지 확인
- 결제창 로딩과 결제 앱 복귀 흐름 확인
- 같은 주소에서 주문자명·전화번호가 다른 주소를 각각 저장할 수 있는지 확인
- 저장 주소 선택 시 주문자명과 전화번호가 자동 입력되는지 확인
- 기성품의 사이즈·색상별 장바구니 분리와 주문 상세 표시 확인
- 단체주문 옵션과 첨부파일의 장바구니·주문서·PDF 보존 확인
- 재고 0인 모든 사이즈의 Sold Out 표시와 재입고 알림 버튼 확인
- 관리자 재고 수정 및 일괄 적용 후 공개 화면 반영 확인
- 태블릿 첫 진입 시 배너만 보이고 상품이 늦게 나타나는 현상 확인
- PC·태블릿·모바일의 검색창, 팝업, 장바구니 버튼, 로그아웃 버튼 텍스트 확인

### P2: 운영 품질 개선 항목

- 첫 화면 이미지와 상품 카드의 로딩 우선순위 조정
- 추천상품 이미지 비율과 카드 크기 통일
- 오류·빈 상태·재시도 화면의 문구와 시각적 통일
- 관리자 주문 상세의 긴 팀원명, 10명 이상 팀원, 가로 스크롤 대응
- PDF의 폰트 크기, 페이지 나눔, 첨부 이미지 크기 최적화
- 운영 로그와 모니터링 알림의 이벤트 코드 표준화
- 사용하지 않는 보관 workflow와 중복 workflow의 정리 여부 검토

## 6. 최종 검수 순서

1. **CI 품질 게이트를 먼저 통과시킵니다.** 포맷, `dart fix`, custom lint, 정적 분석, Flutter 테스트가 모두 성공해야 합니다.
2. **Android 배포 차단 오류를 해결합니다.** minSdk를 24 이상으로 조정하고 Android AAB를 다시 검증합니다.
3. **보안 감사를 실행합니다.** 기본 읽기 전용 설정에서 실패와 경고가 없어야 합니다.
4. **일반 계정과 관리자 계정으로 접근 권한을 확인합니다.** 관리자 데이터와 첨부파일이 일반 사용자에게 노출되지 않아야 합니다.
5. **재고와 결제를 함께 확인합니다.** 결제 성공, 실패, 취소, 중복 호출, 품절 시나리오를 모두 검증합니다.
6. **재입고 알림을 확인합니다.** 0에서 양수로 변경할 때 신청자에게 한 번만 알림이 도착해야 합니다.
7. **장바구니와 주문 상세를 확인합니다.** 상품별 선택 옵션이 누락 없이 보존되어야 합니다.
8. **단체주문과 PDF를 확인합니다.** 새 상품 선택 시 이전 첨부가 제거되고, 실제 선택한 옵션과 이미지만 표시되어야 합니다.
9. **PC·태블릿·모바일을 확인합니다.** 화면 회전과 긴 텍스트에서도 버튼·카드·팝업이 깨지지 않아야 합니다.
10. **최종 승인 후에만 웹 배포와 Android 배포를 각각 실행합니다.** Android는 웹 검수가 끝났다는 이유만으로 자동 배포하지 않습니다.

## 7. 최종 출시 보류 기준

다음 중 하나라도 실패하면 출시를 보류해야 합니다.

- 결제 금액과 주문 금액이 다름
- 결제 취소 후 주문이 확정되거나 재고가 차감됨
- 동일 결제의 주문이 두 건 이상 생성됨
- 재고 0 상품이 결제되거나 재고가 음수가 됨
- 일반 사용자가 관리자 데이터 또는 다른 사용자의 첨부파일에 접근함
- 재입고 알림이 발송되지 않거나 중복 발송됨
- Kakao 로그인 또는 Toss 결제 복귀가 특정 주요 기기에서 멈춤
- Android Play가 minSdk 또는 다른 정책 사유로 AAB를 거부함
- CI 품질 게이트가 실제 검사를 수행하지 않고 통과함
- 단체주문 옵션·첨부·PDF 내용이 서로 다름

## 8. 사용자에게 권장하는 최종 실행 항목

사용자가 지금 직접 해야 할 일은 다음 세 가지로 좁힐 수 있습니다.

첫째, Android 배포는 보류합니다. `minSdkVersion` 수정과 Play Internal Testing 재검증이 끝날 때까지 Android 앱을 배포하지 않습니다.

둘째, 실제 운영 계정과 기기로 결제·로그인·재입고 알림·권한을 확인합니다. 특히 iPhone Safari의 Kakao 로그인과 모바일 결제 복귀를 우선 확인해야 합니다.

셋째, 실제 운영 데이터로 재고 0→양수 변경, 사이즈별 품절, 여러 색상 장바구니, 단체주문 첨부파일, 관리자 일괄 재고 적용을 검수하고 주문번호와 스크린샷을 기록합니다.

나머지 저장소 코드 수정, CI 보완, 자동 테스트 강화, 로그 분석, 문서화, 커밋과 푸시는 요청 범위 안에서 제가 계속 처리할 수 있습니다.
